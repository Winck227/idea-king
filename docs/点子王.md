# 点子王

一句点子或一句没有出路的话进来，班组把它点破为一件能做完、能试用的东西。对话只展示工具生成的 `sentence` 与 `boardPath`；来源、任务、验收、观众和失败原因以展板为准。只有 `deliveryStatus=delivered` 才表示本次约定的交付条件已通过。

旧 [开发文档.md](./开发文档.md) 只用于 `lattice` 格子引擎的历史规格，不规定点子王流程。技能入口是 `.cursor/skills/idea-king/SKILL.md`。

## 模式与班组

- `create_session` 默认 `mode=ideaKing`：两选项身份 `literal` / `spark`；四条件代码 `join` / `not_literal` / `try` / `memory`。显示文案不承担身份识别。
- `mode=lattice` 是自由条件评议的兼容模式，不能把 lattice 的选定当作点子王交付。
- 设置人数为 3–12，默认 5；创建时冻结进 `crewPlan`。固定保留点子王、制作手、收尾手，其他任务槽依次用于收集、分析、挑薄。
- 代码从当前计划任务槽派生允许角色；`callerRole` 只是对当前角色的可选断言，省略不会取得额外权限，`host` 不能绕过限制。重复思考不能重复完成任务槽。
- `spawnAgents=true` 时由宿主实际顺序派发子代理，共用 sessionId。宿主不支持时不得宣称已运行真实多人班组；计划和日志不能证明物理上运行了多个代理。`false` 时当前对话按同一任务顺序执行。

## 固定顺序

1. **创建。** `create_session` 保存原话与初始材料，不在创建时下结论。
2. **点子王冻结。** 至少两个不同真实文件各 `deposit_grab`，记录字面与点破事实，`confirm_marks` 完整提交两选项四条件。
3. **思考。** 按计划任务槽完成收集、分析、挑薄，每槽留下不同的 `deposit_think`。3 人计划没有额外思考槽。
4. **制作。** 依据冻结材料制作脚本与本地依赖；`deposit_file` 登记完整版本，`deposit_manifest` 登记可执行验收。成品输出只写 `artifacts/<id>/out/`。
5. **试跑与验收。** 收尾手 `deposit_run`；代码校验快照和依赖，运行受限脚本，再执行固定验收器。失败不能用一句“已完成”代替。
6. **真实观察。** 验收通过后运行 `npm run observe -- --session <id>`，由真实观察者在独立本机界面查看该版本成品、填写三行并取得 receipt。模型不能代填真实观察。
7. **交卷。** `commit_round` 提交引用与观众记录。代码重验实际产物、清单、材料版本与 receipt，条件未齐仍未完成。最后只展示 sentence 与 boardPath。

没有“先制作再补冻结”的旁路。需要缩小时，回到点子王提出更短 spark，完整重新提交两选项四条件，以同身份替换旧选项；材料、代码或清单变化使旧运行、验收、观察失效，按新版本重做受影响步骤。

## 可执行验收清单

数据契约是 `src/schema.ts` 的 `productManifestSchema`，入口相对 `out/`。`action` 只是说明，不替代 `expected` 的真实操作和断言。不能用 `differsOnInputChange=false` 或任意正则降低必测要求。

页面示例，需真实提供 `#amount`、`#calculate`、`#result`：

```json
{
  "type":"page",
  "entry":"play.html",
  "action":"输入数字并计算两倍结果",
  "expected":{"pageCases":[
    {"steps":[{"op":"fill","selector":"#amount","value":"3"},{"op":"click","selector":"#calculate"}],"assertion":{"selector":"#result","text":"6"}},
    {"steps":[{"op":"fill","selector":"#amount","value":"8"},{"op":"click","selector":"#calculate"}],"assertion":{"selector":"#result","text":"16"}}
  ]}
}
```

页面至少一组真实 `fill` / `click` / `select` 操作，建议提供两组不同输入。由隔离 headless Edge 执行动作；目标结果必须发生变化并精确匹配，不能只断言输入框填入了自身。只写字符、空页面、不存在的按钮、错误结果均不能通过。网络仅允许内存中本地 out 资源快照，外部资源不可用。

CLI 示例：

```json
{
  "type":"cli",
  "entry":"convert.cjs",
  "expected":{"schema":"text","cases":[
    {"input":"abc","output":"ABC"},
    {"input":"xyz","output":"XYZ"}
  ]}
}
```

CLI 运行实际 manifest.entry，至少两组不同输入、不同确定输出，并重复首例验证确定性。JSON 输出用 `schema=json` 和 JSON 预期值。随机结果、固定口号都不能代替功能。

验收能证明当前版本执行了约定动作，不能自动证明独创性、商业价值或人类长期记忆。

## 引用与观众

- join 支持只来自真实 grab。两路材料存在不自动证明交接，点子王仍须说明一方输出怎样成为另一方输入。
- try 支持来自当前版本验收通过的 accept/run，运行必须成功；禁止源码硬编码、完整 grab 或拼接回显、假路径。
- 引用使用已有材料连续子串，markId/optionId 用工具返回值；文字相似不能替代版本一致。
- real 观众必须由独立观察界面签发与实际产物哈希绑定的 receipt。伪造 real、缺凭证、产物变化均不能完成。
- sim 只作模拟诊断，unknown 表示未观察，均不得 delivered。不得改写 remembered 去满足气味。

```json
{"firstStop":"真实第一眼停下的位置","skipped":"真实略过的内容","remembered":"真实记住的话","provenance":"real","artifactHash":"观察界面给出的哈希","receipt":"观察界面签发的凭证"}
```

## 执行与保存边界

- 代码在 QuickJS WebAssembly 中运行，提供受限 CommonJS fs/path 与必要输入输出，不是完整 Node API。无宿主环境变量、网络、子进程或动态宿主导入。
- 输入、依赖与快照只读，只有 out/ 可写；输出总量 4 MiB、内存 64 MiB、执行 5 秒。超限按失败记录。
- 快照、实际依赖、清单与成品内容参与版本绑定。登记后修改快照、材料或资源，不会沿用旧成功证据。
- 更新使用完整读改写事务。证据为唯一事件 ID，不同运行即使同文也独立记录。初始和旧材料保留，版本冲突不得静默覆盖。
- 展板显示 revision、deliveryStatus、观众来源、气味及失败；token 为文本规模估算，不是服务商账单。

## 工具、设置与测试

MCP 与 CLI 共用 create_session、add_fact、confirm_marks、deposit_grab、deposit_think、deposit_file、deposit_manifest、deposit_run、commit_round、get_session。坏 quotes/audience 在共同轮次解析层计数，CLI 文件使用 UTF-8，可含 BOM。非法数据返回结构化错误，不静默成功。

```text
node --experimental-strip-types src/cli.ts commit-round --session <id> --quotes-file quotes.json --audience-file audience.json
npm run observe -- --session <id>
npm run settings
npm test
npm run typecheck
```

设置页为 `http://127.0.0.1:3927/`，配置在 `.cursor/idea-king.json`。人数3–12；主题 ID 限字母、数字、下划线和连字符。页面使用脚本 nonce、上下文转义、同源令牌、请求体积与字段长度限制。正常流程打开可视化设置，不让用户编辑 JSON。
